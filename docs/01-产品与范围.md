# 产品与范围

## 1. 背景

理赔台账通常由业务系统导出成 Excel，人工核对时有两个典型问题：

1. **算得不一样**：应赔金额按合同规则重算后，与表里「实际赔付金额」对不上，但没人能快速说出差在哪一行、差多少；
2. **数据本身有问题**：空值、两位小数以外的金额、赔付比例写成 `80` 而不是 `0.80`、保单号格式不统一——这些脏数据混在台账里，人工核对前得先清洗一遍。

这个项目把「重算 + 对账 + 数据质量检查 + 出报告」固化成一条命令，结果可复现、可进流水线。

## 2. 目标与非目标

### 目标

| 目标 | 判定方式 |
| --- | --- |
| 算得准 | 全程 `Decimal`，`ROUND_HALF_UP`，两位小数；测试覆盖边界 |
| 差异可定位 | 报告逐条给出重算值、原始值、差异额、状态 |
| 脏不丢行 | 解析失败的行进入「异常数据」与「数据质量问题」，行数恒等可核 |
| 可当闸门 | 退出码区分「全一致 / 有差异 / 系统错误」 |
| 可编程 | `AuditEngine` 可被其他程序调用，不必走 CLI |

### 非目标（明确不做）

- 不做 Web 界面、不做数据库、不做用户权限；
- 不替代业务系统的理赔计算，只做**事后审计**；
- 不自动修改原始台账（只读输入，输出独立报告）；
- 不做跨表关联、不做历史版本比对（留给后续版本，见 06 路线图）。

## 3. 用户与场景

| 角色 | 场景 | 关心什么 |
| --- | --- | --- |
| 我自己（开发者） | 每月导出一份台账，跑一遍看差异 | 一条命令、退出码、报告能直接看 |
| 财务/审计同事 | 拿到报告复核异常行 | 异常 sheet 里每行都有原因 |
| 流水线 | 把审计作为发布/结算前检查 | 退出码非 0 能阻断 |

## 4. 功能需求

### FR-1 读取与列校验

- 读取 `.xlsx` / `.xls`，要求 6 个中文列：`保单号`、`客户姓名`、`报案金额`、`免赔额`、`赔付比例`、`实际赔付金额`。
- 缺列直接失败（`InvalidColumnError`），不猜测、不自动改名。

### FR-2 逐行质量校验

对每一行检查：非空、金额两位小数、金额范围、赔付比例 `0~1`、保单号前缀（默认 `CL`）+ 后缀全数字、跨字段业务矛盾（如「实际赔付 > 报案金额」「实际赔付为 0 但应赔大于 0」）。

校验结果**不阻断对账**，全部写进报告的「数据质量问题」sheet。

### FR-3 对账

- 对每行构造 `ClaimRecord`，重算应赔；
- 与原表「实际赔付金额」比较，`|差异| < 0.01` 记为 `一致`，否则 `异常`；
- 解析失败（类型转换异常等）的行标记为 `解析失败`，**保留在明细和异常表里**，不计入一致率分母，但计入「读取总行数」。

### FR-4 汇总与报告

生成 4 个 sheet：审计摘要、对账明细、异常数据、数据质量问题。摘要必须满足：

```
读取总行数 = 成功解析 + 无法解析
成功解析   = 一致 + 异常
一致率     = 一致 / 成功解析 × 100%
```

金额列在 Excel 里是数值（不是文本），带千分位与两位小数。

### FR-5 CLI 与退出码

| 参数 | 作用 |
| --- | --- |
| `--generate-mock` | 先生成模拟数据（默认 50 条、约 10% 差异），再审计 |
| `--input PATH` | 指定输入文件 |
| `--output PATH` | 指定报告路径 |
| 无参数 | 用 `.env` 的默认路径 |

退出码见 [03-详细设计](03-详细设计.md#4-退出码与错误码)。

### FR-6 可编程接口

```python
from insurance_audit.core.engine import AuditEngine

summary = AuditEngine(input_file="claims.xlsx", output_file="report.xlsx").run()
```

`run()` 返回 `AuditSummary`，不调用 `sys.exit`、不依赖 CLI 全局状态。

### FR-7 日志与审计追溯

- 运行日志：控制台 + 10MB 轮转文件，保留 30 份；
- 审计追溯：独立文件，记录流程开始/结束、对账结果、错误；
- 库模块 import 不创建日志目录；入口显式调用 `setup_logging()`；
- 日志目录不可写时降级为仅控制台。

## 5. 非功能需求

| 项 | 要求 | 现状 |
| --- | --- | --- |
| 兼容性 | Python 3.9 与 3.12 行为一致 | CI 双版本矩阵 |
| 金额精度 | 不出现浮点误差 | 全链路 `Decimal` |
| 可复现 | 同一输入同一次配置得到同一报告（审计时间除外） | mock 生成支持 `seed` |
| 只读安全 | 输入文件不被修改 | 只 `read_excel`，从不回写 |
| 失败可见 | 任何被排除的行都要在报告里留痕 | 解析失败收集 + 恒等式测试 |
| 启动健壮性 | 只读目录/无日志权限下 `--help` 可用 | 惰性日志 + 降级 |
| 单机性能 | 1 万行以内 1 分钟内跑完 | 未做基准，pandas 逐行构造，1 万行量级可接受 |

## 6. 验收标准

一个版本可以发布，需要同时满足：

- [x] `ruff check` / `ruff format --check` / `mypy --strict` 全绿；
- [x] `pytest` 全绿，且包含「解析失败不被丢弃」「行数恒等式」「注入差异能被发现」三类回归用例；
- [x] 在干净虚拟环境（Python 3.9）里 `pip install -e ".[dev]"` 后能跑通 `--generate-mock`；
- [x] GBK 控制台下不抛 `UnicodeEncodeError`；
- [x] README 里的命令逐条可执行、路径与退出码与实际一致；
- [x] 文档与代码行为一致（同一个 PR 内同步）。

## 7. 术语

| 术语 | 含义 |
| --- | --- |
| 报案金额 | 客户申请理赔的金额 |
| 免赔额 | 不在赔付范围内的固定金额 |
| 赔付比例 | 扣除免赔额后按比例赔付，`0~1` |
| 应赔（重算值） | `(报案金额 - 免赔额) × 赔付比例`，系统计算的赔付额 |
| 实际赔付 | 原始台账里已经支付的金额，审计对象 |
| 差异 | `|应赔 - 实际赔付|`，超过容差记为异常 |
| 解析失败 | 行数据无法构造成 `ClaimRecord`（类型错误、空值等），单独统计 |
