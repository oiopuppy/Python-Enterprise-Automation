# 质量与测试

质量目标很朴素：**结论不能是错的，错了要能被发现，发现了要能定位。**

## 1. 门禁

每次 push / PR，CI 依次跑四道：

| 关口 | 命令 | 失败意味着 |
| --- | --- | --- |
| 代码质量 | `ruff check src/ tests/` + `ruff format --check src/ tests/` | 风格/潜在 bug/未排序 import |
| 类型检查 | `mypy --strict src/ --ignore-missing-imports` | 类型不闭合，往往是逻辑漏洞（如 `Optional` 没判空） |
| 安全扫描 | `bandit -r src/ -ll` | 高风险模式（`eval`、`subprocess`、弱随机） |
| 测试 | `pytest --cov=src/insurance_audit`（3.9 与 3.12 各一次） | 行为回归 |

CI 之外还有 pre-commit（trailing-whitespace、end-of-file、yaml、ruff），本地提交前可先挡一层。

命中 `S101`（测试里的 `assert`）已在 `tests/**` 豁免；`N818`（异常类名不带 `Error` 后缀）在 `utils/exceptions.py` 豁免，因为类名是 v1 的公开 API。

## 2. 测试分布

共 **58 个用例**，全部为 Python 标准库 `pytest` + `pytest-mock`，无网络、无外部服务。

| 文件 | 数量 | 覆盖对象 |
| --- | --- | --- |
| `tests/test_calculator.py` | 21 | 赔付公式：免赔、比例、边界、四舍五入、批量计算、异常输入 |
| `tests/test_integration.py` | 10 | 完整流水线：一致/注入差异/解析失败/报告 sheet/退出码 |
| `tests/test_main.py` | 5 | CLI：缺文件、全一致、有异常、解析失败、`--generate-mock` 落盘位置 |
| `tests/test_models.py` | 7 | `ClaimRecord` 字段校验、别名、`reconcile()` 判定 |
| `tests/test_reconciler.py` | 6 | 逐行构造、容差、汇总、解析失败被记录而非丢弃 |
| `tests/test_validator.py` | 9 | 缺列、各字段约束、脏数据只提示不阻断 |

最关键的三个用例：

- `test_full_pipeline`：20 条全一致 → 退出码 `0`，报告 4 个 sheet；
- `test_full_pipeline_with_injected_anomalies`：注入差异 → `unmatched >= 15`，`matched + unmatched == 20`；
- `test_pipeline_records_parse_errors`：混入非法行号 → `读取总行数 = 2`、`无法解析 = 1`，报告里能查到那一行。

未覆盖的部分主要是：`writer.py` 的异常分支、`reader.py` 的 IO 失败分支、`config.py` 的环境变量组合、`main.py` 的 `SecurityException`/未捕获异常分支。这些属于「难在单测里制造」的路径，目前靠手工验证兜底。

CI 不设覆盖率阈值——阈值容易催生为凑数而写的测试；这里用「关键路径必须有用例」来约束。

| 行为 | 用例 |

## 5. 手工验证清单

自动测试覆盖不到「进程真实退出码」「控制台编码」「容器启动」这类东西，发布前手工过一遍：

1. 从**另一个目录**运行 `python -m insurance_audit --generate-mock --input xxx.xlsx --output yyy.xlsx`，确认文件落在指定位置；
2. 中文 Windows 控制台运行，确认不出现 `UnicodeEncodeError`、不输出 ANSI 乱码；
3. 把输入文件名改错，确认退出码为 `1`（`echo $LASTEXITCODE`）；
4. 把 `logs/` 设为只读，确认程序降级运行而不是崩溃；
5. 打开报告，确认 4 个 sheet、摘要金额是数值、异常表包含解析失败行。

## 6. 已知限制

诚实记录，避免误以为已经覆盖：

- **Docker 镜像未在本地构建验证**：`PROJECT_ROOT=/app` 与健康检查按设计写好，但没有实际 `docker build` 过；
- **性能未基准**：逐行构造 `Decimal`，1 万行大约在秒级，但没有正式的基准数字；
- **明细金额是文本**：`对账明细` 的金额列保留原值字符串，Excel 里不能直接求和（摘要 sheet 的金额是数值）；
- **`AuditSummary.execution_time` 字段未写入**：目前恒为默认值，是遗留字段；
- **无分支保护**：私有/免费仓库不支持，靠流程纪律；
- **单表对账**：不做跨表、跨期、历史比对；
- **xls 支持依赖环境**：`.xls` 走 `xlrd` 时若无该包会报错，README 只推荐 `.xlsx`。
