## 2. 本次整改（develop 分支）

起点是「CI 三件套全红」：`ruff` 81 个错误、`ruff format` 13 个文件待格式化、`mypy --strict` 16 个错误；跑起来还有「解析失败静默丢行」「退出码恒为 0」「换目录跑就读不到文件」三个真问题。

### PR #1 `chore/ci-baseline` — 先把门禁弄绿

- `pyproject.toml`：`ruff.target-version` 改 `py39`，`mypy.python_version` 改 `3.10`（mypy 1.20 起不支持 3.9 目标，3.9 运行时兼容性交给测试矩阵）；
- `pytest.ini` 删除，配置统一到 `pyproject.toml`（否则 `-p no:cacheprovider` 被覆盖）；
- 30 处 ruff 自动修复、18 个文件格式化、8 处手修（`B904` 补 `from e`、mock 的 `S311` 加 `noqa`）；
- 7 处 mypy 修复（`Optional` 判空、`as_tuple().exponent` 收窄、`dict` 参数化、`reconciler` 改用 `model_validate`）；
- 合并提交 `49a4933`。

### PR #2 `fix/audit-correctness` — 审计结论要对

- 解析失败不再 `continue` 静默丢弃：进 `parse_errors`，明细里保留「解析失败」行，恒等式 `读取总行数 = 成功解析 + 无法解析`；
- 退出码修复：删掉提前 `return`，`EXIT_*` 常量贯穿到 `sys.exit`，有异常返回 `1`；
- 路径统一：`--input` / `--output` 上线，mock 默认写入配置的输入路径，不再落在 CWD；
- 报告：4 个 sheet，摘要金额改为数值单元格，新增「数据质量问题」；
- 跨字段规则（实际赔付 > 报案金额）只提示、不抛错——曾用 `model_validator` 硬拒，结果把要审计的差异行当成解析失败丢了；
- 合并提交 `eb7bd50`。

### PR #3 `fix/runtime-packaging` — 能在真实环境跑

- 日志惰性初始化：`get_logger()` 不再在 import 时建文件，`setup_logging()` 由 `main()` 调用；文件不可写时降级为控制台；
- `ColorFormatter` 不再把 ANSI 写进日志正文（`try/finally` 恢复 `levelname`）；
- 控制台 GBK 兜底：`errors="replace"`，`¥` 改「元」；
- `PROJECT_ROOT` 环境变量，Docker 内设为 `/app`；健康检查改成真的能启动；
- `run_audit` 改为调用 `AuditEngine`，删掉一份平行实现；
- 赔付公式去重：`ClaimRecord.calculate_payout` 委托核心函数（函数内导入避免循环）；
- 删除 `gunicorn` / `supervisor`、`SECRET_KEY` / `ENABLE_DATA_ENCRYPTION`（从来没有实现）；
- 合并提交 `c394553`。

## 3. 决策清单

详细理由见 `02-架构与设计.md` 的 D-01 ~ D-10，这里只列「为什么当时这么选」的一句话版：

| 编号 | 决策 | 一句话理由 |
| --- | --- | --- |
| D-01 | 金额全用 `Decimal` | `float` 的分位误差在审计里不可接受 |
| D-02 | 解析失败不丢行 | 少行的报告比报错更危险 |
| D-03 | 跨字段规则只提示 | 差异行正是审计对象，不能当非法数据丢掉 |
| D-04 | 日志惰性 | import 就建目录，只读环境和 `--help` 都会崩 |
| D-05 | `PROJECT_ROOT` 显式化 | `parents[3]` 在容器里指到 Python 安装目录 |
| D-06 | 公式唯一实现 | 两处实现必然漂移 |
| D-07 | 退出码 `if/else` | 提前 `return` 会跳过 `sys.exit` |
| D-08 | src 布局 | 摆脱「必须在仓库根运行」 |
| D-09 | CI 双版本 | 声明支持 3.9 就得真的测 3.9 |
| D-10 | 删无用依赖 | 没有 Web 服务，`gunicorn` 是模板残留 |

## 4. 风险台账

| 风险 | 影响 | 现状 | 计划 |
| --- | --- | --- | --- |
| Docker 镜像未本地构建 | 部署时才发现路径/权限问题 | 中 | 下个版本前补一次 `docker build` + 冒烟 |
| 明细金额是文本 | 用户可能在 Excel 里直接求和，得到 0 | 中 | 文档已注明；可选加一列数值副本 |
| 性能未基准 | 大文件可能慢到影响批量调度 | 低 | 1 万行基准后再决定要不要优化 |
| 无分支保护 | 可能误推 `main` | 低 | 靠纪律；仓库付费后可开保护 |
| `execution_time` 未写入 | 报告里字段无意义 | 低 | 要么补，要么删 |
| `xls` 依赖 `xlrd` | 用户拿老文件来会报错 | 低 | README 明确推荐 `.xlsx` |

## 5. 路线图

不承诺时间，只记方向：

- **2.1**：性能基准；`--json` 机器可读输出，方便接调度/看板；
- **2.2**：报告加汇总图表（按机构/时段）；支持多文件批量；
- **3.0**：赔付规则可配置（阶梯比例、按险种）；跨期对账。
