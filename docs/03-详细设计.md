# 详细设计

本文是「对接方和排障方」的接口手册：输入长什么样、输出长什么样、失败时拿到什么。

## 1. 输入数据契约

### 1.1 文件

- 格式：`.xlsx` 或 `.xls`（其他扩展名只 warning，仍尝试按 Excel 读）；
- 第一个 sheet 作为数据表，表头在第一行；
- 空文件/空表：返回空摘要（各计数为 0），报告正常生成。

### 1.2 列

| 列名 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `保单号` | 文本 | 是 | 以 `INSURANCE_POLICY_PREFIX`（默认 `CL`）开头，其后全是数字；非空 |
| `客户姓名` | 文本 | 是 | 非空 |
| `报案金额` | 金额 | 是 | `INSURANCE_MIN_CLAIM_AMOUNT ~ INSURANCE_MAX_CLAIM_AMOUNT`；最多两位小数 |
| `免赔额` | 金额 | 是 | `0 ~ 99999999.99`；最多两位小数 |
| `赔付比例` | 小数 | 是 | `0 ~ 1`（`0.8`，不是 `80`）；最多两位小数 |
| `实际赔付金额` | 金额 | 是 | `0 ~ 99999999.99`；最多两位小数 |

缺列 → `InvalidColumnError`（`DAT-0102`），进程退出码 `1`，不生成报告。

### 1.3 允许的脏数据（进报告、不阻断）

| 情况 | 结果 |
| --- | --- |
| 某行金额为空 / 不是数字 | 该行 `解析失败`，进异常表与明细，不计入一致率 |
| 金额超过两位小数 | 「数据质量问题」提示，**仍参与对账**（按原值计算） |
| 赔付比例 `> 1` | 「数据质量问题」提示，仍参与对账 |
| 保单号前缀/格式不符 | 「数据质量问题」提示，仍参与对账 |
| 实际赔付 > 报案金额 | 「数据质量问题」提示，仍参与对账（这正是要审计的差异） |
| 实际赔付为 0 但应赔 > 0 | 「数据质量问题」提示，仍参与对账 |

原则：**格式问题不阻断业务判断**；只有「无法转成数字」才判定为解析失败。

## 2. 输出报告契约

一个 Excel，固定 4 个 sheet。

### 2.1 审计摘要

三列：`审计项目` / `数值` / `单位`。

| 审计项目 | 单位 | 说明 |
| --- | --- | --- |
| 审计时间 | — | `YYYY-MM-DD HH:MM:SS` |
| 读取总行数 | 条 | Excel 数据行数（不含表头） |
| 成功解析 | 条 | 能构造成 `ClaimRecord` 的行 |
| 无法解析 | 条 | 解析失败行 |
| 一致记录数 | 条 | `|差异| < 0.01` |
| 异常记录数 | 条 | `|差异| >= 0.01` |
| 一致率 | % | `一致 / 成功解析 × 100` |
| 总报案金额 | 元 | 仅成功解析行 |
| 总原始赔付 | 元 | 仅成功解析行 |
| 总系统核算 | 元 | 仅成功解析行 |
| 总差异金额 | 元 | 各异常行差异之和 |

恒等式（测试会校验）：

```
读取总行数 = 成功解析 + 无法解析
成功解析   = 一致 + 异常
```

金额行写入真正的数值单元格，`#,##0.00` 格式；百分比行 `0.00"%"`。

### 2.2 对账明细

| 列 | 类型 | 说明 |
| --- | --- | --- |
| 保单号 | 文本 | |
| 客户姓名 | 文本 | |
| 报案金额 | 数值 | 2 位小数显示 |
| 免赔额 | 数值 | |
| 赔付比例 | 数值 | `0.00` 格式 |
| 原始赔付金额 | 数值 | 台账里的值 |
| 系统核算金额 | 数值 | 重算值 |
| 差异金额 | 数值 | 绝对值 |
| 审计状态 | 文本 | `一致` / `异常` / `解析失败` |

解析失败的行也在内，金额列留空、状态为 `解析失败`。

金额与比例写入真正的数值单元格（`#,##0.00` / `0.00` 格式），可以直接筛选、求和。
Excel 只是展示层：逐分精确核对以 `系统核算金额` 为准，重算在 `Decimal` 下完成。

### 2.3 异常数据

`审计状态 ∈ {异常, 解析失败}` 的行，列与明细相同。

### 2.4 数据质量问题

| 列 | 说明 |
| --- | --- |
| 问题类型 | `字段校验` / `无法解析` |
| 行号 | Excel 行号（表头是第 1 行，数据从 2 开始） |
| 字段 | 出问题的列名；整行失败为 `整行` |
| 原因 | 人类可读的原因 |

### 2.5 JSON 摘要（`--json` / `--json-out`）

加 `--json` 时，摘要 JSON 输出到 **stdout**（日志改走 stderr，stdout 保持纯 JSON，可直接管道消费）；加 `--json-out PATH` 时，同一份摘要同时落盘。两者可以一起用，也可以只用一个：

```bash
insurance-audit --json > out.json                     # 管道/重定向
insurance-audit --json | jq .summary.match_rate       # 直接在流水线里取字段
insurance-audit --json-out reports/2026-11.json        # 顺便落盘
```

```json
{
  "tool_version": "2.0.0",
  "generated_at": "2026-11-10 20:00:00",
  "input": {
    "path": "data/claims.xlsx",
    "rows": 10000,
    "sha256": "3f786850e387550fdab836ed7e6dc881de23001b..."
  },
  "output": {
    "path": "reports/report.xlsx"
  },
  "summary": {
    "source_records": 10000,
    "total_records": 10000,
    "parse_error_records": 0,
    "matched_records": 9084,
    "unmatched_records": 916,
    "match_rate": 90.84,
    "total_claim_amount": "25457485.00",
    "total_actual_payout": "16172086.37",
    "total_calculated_payout": "16172059.79",
    "total_discrepancy": "10494.26"
  },
  "parse_errors": [],
  "quality_issues": [],
  "execution_time": "2.70s"
}
```

约定：

- 金额字段在 JSON 里是字符串，避免 `float` 丢精度；
- `input.sha256` 是输入文件哈希，用于审计留痕；`input.rows` 是读取总行数（含解析失败行）；
- `parse_errors` 元素为 `{row, policy_id, reason}`；`quality_issues` 元素为 `{row, field, reason}`，与报告的「数据质量问题」一致；
- 明细不写进 JSON（大文件会失控），完整明细看 Excel 的「对账明细」sheet；
- 退出码语义不变，JSON 只是附加产物。

## 3. 模块接口

```python
# 入口
insurance_audit.main.main() -> None                      # sys.exit(exit_code)
run_audit(input_path: Path, output_path: Path,
          emit_json: bool = False, json_out: Optional[Path] = None) -> int

# 编排
class AuditEngine:
    def __init__(self, input_file: Optional[str] = None,
                 output_file: Optional[str] = None) -> None
    validation_errors: list[DataValidationError]          # 最近一次 run() 的字段级问题
    def run(self) -> AuditSummary

# 计算
calculate_payout(claim_amount: Decimal, deductible: Optional[Decimal],
                 ratio: Optional[Decimal], policy_id: str = "") -> Decimal

# 校验
validate_columns(df: pd.DataFrame) -> None               # 缺列抛 InvalidColumnError
validate_row(data: Mapping[str, Any], row_index: int) -> list[DataValidationError]
validate_dataframe(df: pd.DataFrame) -> list[DataValidationError]

# 数据
read_excel(file_path: Union[str, Path]) -> pd.DataFrame
write_excel(df: pd.DataFrame, file_path: Union[str, Path]) -> Path
auto_adjust_column_width(writer: pd.ExcelWriter) -> None
generate_mock_data(num_records: int = 50, output_file: Optional[str] = None,
                   anomaly_ratio: float = 0.1, seed: Optional[int] = None) -> Path

# 对账
reconcile_dataframe(df: pd.DataFrame) -> tuple[pd.DataFrame, AuditSummary]

# 报告
generate_report(detail_df: pd.DataFrame, summary: AuditSummary,
                output_path: Union[str, Path],
                validation_errors: Optional[list[DataValidationError]] = None) -> Path
build_json_payload(summary: AuditSummary, input_file: str = "",
                   output_file: str = "",
                   validation_errors: Optional[list[DataValidationError]] = None) -> dict[str, Any]
write_json_report(payload: dict[str, Any], output_path: Union[str, Path]) -> Path

# 日志
get_logger(name: str) -> logging.Logger                  # 不配置 handler
setup_logging() -> None                                  # 幂等
get_audit_logger() -> AuditLogger                        # 惰性单例
```

## 4. 退出码与错误码

### 4.1 退出码（进程级）

| 码 | 常量 | 触发条件 |
| --- | --- | --- |
| `0` | `EXIT_OK` | 审计完成，`unmatched == 0` 且 `parse_error == 0` |
| `1` | `EXIT_AUDIT_ISSUE` | 有对账异常 / 解析失败 / 输入文件不存在 / 业务性数据异常 |
| `2` | `EXIT_SYSTEM_ERROR` | `SystemException`（IO、配置） |
| `3` | `EXIT_SECURITY_ERROR` | `SecurityException` |
| `9` | `EXIT_BUSINESS_ERROR` | 其他 `InsuranceAuditError` |
| `99` | `EXIT_UNEXPECTED` | 未捕获异常 |

### 4.2 错误码（异常级）

`InsuranceAuditError` 的 `error_code` 为 `前缀-四位数字`，并会拼进异常消息 `[BIZ-0101] ...`。

| 错误码 | 异常类 | 含义 | 退出码 |
| --- | --- | --- | --- |
| `ERR-0000` | `InsuranceAuditError` | 基类默认 | `9` |
| `BIZ-0001` | `BusinessException` | 业务异常基类 | `9` |
| `BIZ-0101` | `ClaimAmountExceedsLimitError` | 报案金额超过年度上限 | `9` |
| `BIZ-0102` | `NegativeClaimAmountError` | 报案金额为负 | `9` |
| `BIZ-0103` | `InvalidDeductibleError` | 免赔额非法 | `9` |
| `BIZ-0104` | `InvalidRatioError` | 赔付比例非法 | `9` |
| `BIZ-0201` | `ReconciliationMismatchError` | 对账不一致（供库调用方主动抛出） | `9` |
| `DAT-0001` | `DataException` | 数据异常基类 | `1` |
| `DAT-0101` | `FileNotFoundError` | 输入文件不存在 | `1` |
| `DAT-0102` | `InvalidColumnError` | 缺少必需列 | `1` |
| `DAT-0201` | `DataValidationError` | 单字段/单行校验失败（**不抛出，收集用**） | — |
| `SYS-0001` | `SystemException` | 系统异常基类 | `2` |
| `SYS-0101` | `IOFailure` | 读写 Excel 失败 | `2` |
| `SYS-0201` | `ConfigurationError` | 配置项非法 | `2` |
| `SEC-0001` | `SecurityException` | 安全异常 | `3` |

## 5. 配置

优先级：**环境变量 > `.env` > 代码默认值**。`.env` 不存在时会尝试加载 `.env.example`（方便第一次跑）。

| 分组 | 变量 | 默认 | 说明 |
| --- | --- | --- | --- |
| 路径 | `PROJECT_ROOT` | 源码根 | 容器内设为 `/app` |
| 应用 | `APP_NAME` | 保险理赔审计系统 | 显示名 |
| | `APP_ENV` | `development` | `production` 时 `is_production=True` |
| | `APP_DEBUG` | `true` | |
| 日志 | `APP_LOG_LEVEL` | `INFO` | |
| | `APP_LOG_FILE` | `logs/audit.log` | 相对 `PROJECT_ROOT` |
| | `APP_LOG_MAX_BYTES` | `10485760` | 10MB |
| | `APP_LOG_BACKUP_COUNT` | `30` | |
| 审计 | `AUDIT_ENABLED` | `true` | |
| | `AUDIT_LOG_FILE` | `logs/audit_trail.log` | |
| 数据 | `DATA_INPUT_FILE` | `sample_claim_data.xlsx` | 相对 `PROJECT_ROOT`，可给绝对路径 |
| | `DATA_OUTPUT_FILE` | `final_settlement_report.xlsx` | |
| | `DATA_OUTPUT_DIR` | `reports` | |
| 业务 | `INSURANCE_DEFAULT_DEDUCTIBLE` | `500` | |
| | `INSURANCE_DEFAULT_RATIO` | `0.80` | |
| | `INSURANCE_DECIMAL_PLACES` | `2` | `0~10` |
| | `INSURANCE_ANNUAL_LIMIT` | `500000` | |
| | `INSURANCE_POLICY_PREFIX` | `CL` | |
| | `INSURANCE_MIN_CLAIM_AMOUNT` | `0.01` | |
| | `INSURANCE_MAX_CLAIM_AMOUNT` | `99999999.99` | 必须大于最小值 |

配置在进程启动时读取一次（`Settings` 单例）；`--input` / `--output` 优先级高于配置。非法配置抛 `ConfigurationError`（`SYS-0201`），退出码 `2`。

## 6. CLI

```
insurance-audit [--generate-mock] [--input PATH] [--output PATH]
```

`--help` 不初始化日志、不创建目录，可在只读环境执行。
