# 文档索引

这个目录记录「为什么做成这样」，代码本身只回答「怎么做的」。写得比较细，但都是这个项目实际会用到的东西，不是模板。

## 30 秒版本

- 输入：6 列理赔台账 Excel
- 处理：`(报案金额 - 免赔额) × 赔付比例` 重算 → 与「实际赔付金额」逐条比 → 容差 0.01 元
- 输出：4 个 sheet 的审计工作簿 + 退出码闸门
- 技术栈：Python 3.9+ / pandas / openpyxl / pydantic v2 / Decimal

## 阅读路径

**只想用**：README 的「安装 / 使用」→ 03 的「数据契约」。

**想改代码**：01（范围与验收）→ 02（分层与决策）→ 03（接口与错误码）→ 04（测试怎么跑）。

**接手或排障**：03 的「错误码与退出码」→ 04 的「已知限制」→ 06 的「风险台账」。

## 写作约定

- 文档里的接口、默认值、退出码以代码为准；改了行为要同步改文档，和代码放在同一个 PR 里。
- 不写「企业级」「央企」「行业领先」这类形容词——它们不可验证。写清楚做了什么、代价是什么。
- 决策记录写「当时为什么这么选」，不写「最终方案是 X」就完事。
